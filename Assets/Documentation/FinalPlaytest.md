# 最终版试玩入口与范围

打开 Assets/Scenes/MainGame.unity 后 Play。不要打开 Unity 的 _Recovery 备份作为游戏场景。

## 三个核心操作

1. 点 Money Tracker，查看总余额、房租预留、未分配资金。Reserve 给下一次房租预留，Release 解除。不会增加或扣除总余额。主动购买用未分配资金；必要生活费仍会结算，可能动用预留；交租会自动消耗相应预留。
2. 点 Fridge，只查看存量和今晚支出。采购通过日志事件进行；库存用完，正常每天支付 $20 伙食费。其他必要支出另外计算。
3. 点 Journal，处理事件和 End Day。短工当天到账，长工三天后到账；表情反映状态，恢复活动可以安排休息。日历只显示事先知道的日期与玩家确认的事项。

## 这轮固定的范围

- 30 天；家庭生活费为固定收入，打工为主动选择。
- 采购重点分别为交租前、到账后、核对现有库存。
- 玩家原创四种像素表情替代心情数字和进度条。
- 现金、饥饿购物、愿望单和提醒是辅助内容，保留但不继续扩展事件库。
- 结局最多三条基于实际记录的回顾；没有把某种消费固定判定为错误。
- 暂不扩充新资源系统、随机事件池或新的月份。

## 最后一次人工试玩

- 预留再解除，确认总余额不变，未分配资金正确变化。
- 打开冰箱，确认只有库存和支出说明，没有采购按钮。
- 第11天零食计划：$36 现在付，明天起15天付费伙食每天少扣 $3。计算今天、明天生活费及房租，确认“未来省钱”不等于“今天付得起”。
- 有食物库存时没有额外返现，优惠按自然日到期，不能靠堆库存延长。
- 交租前比较大包装与小包装；生活费到账后再判断一次。
- 一次检查现金流：长工的确认收入是否来得及支付下一笔账单。
- 看结局能否用一句话解释本局遇到的问题，而不必翻完整流水。

程序检查通过：预算守恒、预留与解除、必要支出、交租、库存页面和零食优惠期限、表情分档、文字布局、30 天流程和重新开始。程序路线只能检查规则与可行性，不能证明玩家学习效果。人类试玩重点放在信息是否清楚、是否确实需要查看和计算；随后以修 bug 与提交为主。
