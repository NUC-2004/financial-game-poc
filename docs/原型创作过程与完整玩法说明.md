# 大学生金融决策游戏：原型创作过程与完整玩法说明

整理日期：2026年10月8日。实现内容以仓库提交 `1164e01` 的原型为准。

这是一份供组员共同撰写 Proof-of-Concept 说明 PDF 使用的中文资料。它详细记录创作过程、已实现功能、玩法、测试与反思，篇幅超过最终提交要求。最终 PDF 仍应压缩至1–2页，不需要把本资料全部放进去。游戏中的界面和事件文字为英文，这里用中文解释。

## 一、游戏想解决什么问题

游戏面向正在承担更多财务责任的大学生，包括开始管理生活费、兼职收入和日常账单的学生。我们希望让玩家在模拟生活中练习安排有限资金，并观察一次决定对之后几天的影响。

项目关注的是金融知识的实际运用。例如，知道“应该提前留钱交房租”和在多个消费机会面前真正留足房租，是两件不同的事。游戏希望让玩家结合余额、付款日期、预计收入和生活需求作出决定。

我们的目标不是把所有财务困难归咎于个人选择，也不是规定越少花钱就越正确。低收入和较高生活成本本身就会限制选择。当前原型只是一种简化的练习环境，不能完整代表学生的现实处境。

## 二、从构想到原型的过程

### 1. 确定表达方式和学习方向

最初构想参考了《60 Seconds!》通过日记和文字事件推动时间、让选择产生后果的呈现方式。我们没有制作开局限时搜集物资，而是考虑用不同初始资源开始游戏，让玩家管理接下来的生活。

完整构想曾考虑60个游戏日和更大的事件池。本次作业先缩小为10天、5个事件，以便完成并检查核心流程。当前没有60秒倒计时，也没有实时操作压力；时间通过玩家点击 End Day 推进。

由于小组有 Unity 开发经验，我们选择 Unity 制作原型。现阶段优先完成文字事件、经济系统和可用的界面，视觉内容仍较简单。

### 2. 先搭建基础系统和信息界面

第一步实现日期推进、账户余额、每日生活费、房租和工资。接着补齐日志面板与记账本面板，让玩家既能看到当天情况，也能查询将来需要支付的费用。

这一阶段有了可以运行的时间与经济流程，但还没有事件回应选项。它能展示自动结算，却不足以让玩家作出决定。因此，下一步加入了五个有实际后果的事件。

### 3. 加入能够影响后续状态的选择

五个事件安排在第1、3、5、7、9天，每个事件有三个回应。选择可以立即扣钱、增加食物储备，或安排一笔稍后到账的收入。

我们希望后果不只体现为当场加减钱。例如，购买食材会减少之后几天的食物支出；教材退款要在交租日之后才到账；额外兼职的报酬也不是马上可用。记账本同时记录现金交易和玩家的决定。

文案采用日常生活中的夸张和冷幽默。例如，冰箱事件的开头是：“你打开冰箱。灯还亮着。好消息到此为止。”幽默主要用于呈现学生生活中的琐事，金额、日期和选项结果则尽量写清楚。

### 4. 讨论是否加入其他指标

开发过程中，我们发现：如果只看钱，玩家可能总是选择花钱最少的方案。我们讨论过心情、满意度和消费后的随机事件，但没有在当前原型中实现这些系统。

现有食物储备是实际影响后续支出的资源。友情、休息、学习便利等只存在于文字描述中，没有独立数值，也没有因不参加聚会而扣除心情或友情的机制。这使原型比较容易实现，但也保留了部分选择在金钱上明显更有利的问题。

### 5. 调整数值，增加现金不足的可能性

最初的开局资金为 $850、$900、$950。测试发现，当时测试过的选择组合都能完成游戏，玩家很少需要为后续付款担心。

之后把开局资金改为 $740、$760、$780，保留原有房租、生活费、工资和事件价格。这样，一些连续支出会导致交不起房租，或者交完房租后撑不到发薪日，同时仍保留多条可行路线。

这一步提高了财务压力，但不能据此断言策略性或学习效果已经提高。

### 6. 获得课堂反馈，重新考虑策略体验

项目发起者在课堂上让老师试玩。根据其转述，老师反馈没有明显体验到策略的运用。这里记录的是转述的反馈，不是逐字引语，也不是正式用户研究结论。

此前 Full Paper Draft 的书面反馈认可了所识别的专家策略，但指出方案与这些策略之间的联系不够清楚，并建议使用图示帮助解释。这是此前论文的书面反馈，应与此次课堂试玩反馈分开叙述。

我们的分析是：游戏已经呈现了金融内容，但部分选项仍然可以通过直接比较金额来判断。玩家未必需要查看账单、提前留钱或调整计划。下一阶段应改进决策之间的取舍和联系，而不只是提高难度或增加事件数量。以上改进目前还只是计划。

## 四、玩家如何操作

1. 用指定 Unity 版本打开仓库中的 MainGame 场景，点击 Play。
2. 系统自动生成本局初始资金，进入第1天。
3. 在主画面查看日期、余额、食物储备和状态提示。
4. 点击右下角 Daily Journal，阅读当天日志。
5. 如果当天有事件，从三个选项中选择一个。也可以先关闭日志，打开左下角 Ledger 查看账单，再回到日志。
6. 选择后，日志显示结果，相关余额、储备或待到账收入随之更新。
7. 点击 End Day，结算当天费用并推进日期。没有新事件的日期，可以阅读结算信息后直接结束当天。
8. 重复以上过程，直到完成第10天或付款失败。
9. 本局结束后可查看记账本；点击 New Run 开始新的一局。

打开或关闭面板不会推进时间，也不会扣钱。当前没有独立开始菜单或单独的“随机开局”按钮；随机资金已实现，独立菜单仍未实现。进行中的一局不能通过 New Run 随意覆盖，按钮在本局结束后才出现。

### 每天的准确结算顺序

```text
进入当天：如有到期收入，先到账
    ↓
阅读当天事件，查看余额和未来安排
    ↓
作出选择：立即支出／增加食物／登记未来收入
    ↓
点击 End Day
    ↓
检查是否能支付当天完整生活费
    ├─ 不足：本局结束，不扣除部分生活费
    └─ 足够：支付食物费或消耗食物储备，再支付其他必要费用
                 ↓
            如果当天房租到期，尝试支付房租
                 ├─ 不足：本局结束，已支付的生活费保留
                 └─ 足够：扣房租，更新下次到期日
                              ↓
                        第10天：完成本局
                        其他日期：进入下一天
```

因此，仅有 $500 并不一定能在房租日过关：玩家还需要支付当天 $10 或 $30 的生活费。余额刚好够支付是允许的，不会仅因为余额为零而立即结束；之后需要付款时才重新检查。

## 五、界面与功能清单

### 1. 主画面

- 日期和天数：显示当前是第几天、共10天，以及具体日期。
- 余额：显示目前实际可用的资金。
- 食物储备：显示还能代替多少天的食物支出。
- 状态文字：提示有待处理的决定、最近结算信息或本局结束情况。
- Ledger 按钮：打开记账本。
- Daily Journal 按钮：打开日志。

### 2. 日志面板 JournalPanel

- 顶部显示当天日期、余额、食物天数、当天生活费、房租日期和常规工资日期。
- 有事件时显示标题、情境和三个回应选项。
- 选项写明已知的立即费用、增加的食物，或延迟收入日期。
- 如果余额不足以支付选项的立即费用，选项不可点击，并显示 Not enough cash。
- “付得起选项”不代表“选完仍付得起房租”；系统不会替玩家预留房租。
- 当天事件尚未回应时，End Day 不可用。选择“跳过”或零支出方案也算一次回应。
- 选择后选项消失，显示结果文字，End Day 可用。
- 每个事件只能处理一次；关闭重开日志不会重置事件，重复请求也不会再次获得收益。
- 没有事件的日期显示普通日志与最近结算信息，不会额外随机产生新事件。
- 本局结束时自动显示结果；End Day 隐藏，New Run 出现。

### 3. 记账本面板 LedgerPanel

左侧是安排与概况：

- 下一次房租日期、金额，以及是否今天到期。
- 常规工资日期、金额，以及是否已经收到。
- 朋友生日日期，以及今天、即将到来或已经过去的状态。
- 每日食物费和其他必要费用的规则。
- 当前食物储备和当天实际生活费。
- 已经通过事件安排、但还未到账的收入。

右侧是可滚动的记录：

- 现金交易按最新在前的顺序排列。
- 每笔交易有日期、说明、收入或支出金额，以及交易后的余额。
- 收入显示为绿色，支出显示为红色。
- 初始资金也会记录为一笔 Opening balance。
- 延迟收入只有真正到账后才成为现金交易，之前只显示在待到账安排中。
- 现金交易下方另有 Decision History，按最新在前展示事件、所选方案和结果说明。
- 零支出的选择也有决策记录，但不会制造一笔金额为零的现金交易。

两个面板不会同时展开。结束游戏后仍可查看本局记录，但重新开局会清除旧记录。当前没有导出账本、跨局保存、跨局并排比较或自动因果分析功能。

### 4. 食物储备

食物不是独立的饥饿值，而是“已经解决了几天的食物需求”。购买或领取后立即加入储备，当天就能使用。

例如，第1天购买5天食材后，当晚只支付 $10 其他费用，并把储备由5天减为4天。如果没有其他食物变化，第1至第5天都不再扣 $20 食物费。

多个来源的储备可以累加。当前没有保质期、储存容量、食物出售或剩余食物折现机制。不能把未花现金与剩余食物视为完全相同的资源。

### 5. 延迟收入与结束处理

当前有两种事件延迟收入：教材退款和额外兼职报酬。选择时确定到账日，进入该日期时自动到账，不需要再次点击领取。

如果玩家在到账日前已经失败，本轮不会继续推进日期，也不能靠尚未到账的钱支付当前费用。重新开局会清空这些待到账款项。

失败画面说明需要支付多少、当前可用资金和差额。完成画面说明已完成10天并显示最终余额。系统没有额外的星级评分或“正确选择”分数。

## 六、全部五个事件及其详细后果

### 事件一：冰箱投诉了

英文标题：The Fridge Has Filed a Complaint。出现时间：第1天，9月11日。

情境：打开冰箱，唯一的好消息是灯还亮着。玩家可以提前准备几天的食物，但需要考虑9月15日的房租。

| 选择 | 立即效果 | 后续效果 |
| --- | --- | --- |
| 批量备餐 | 支出 $80，增加5天食物 | 从当天起可抵扣5次每日 $20 食物费 |
| 少量采购 | 支出 $36，增加2天食物 | 从当天起可抵扣2次每日食物费 |
| 暂时保留现金 | 无立即支出，不增加食物 | 没有储备时，每天仍支付 $20 食物费 |

反馈重点：大采购占用更多当前现金，但在食物都能被用上的情况下，单位成本较低；小采购占用资金较少。结果文案会调侃空冰箱和备餐，但不会额外随机扣钱。

希望涉及的策略：事先规划食物需求、比较总支出、为已知账单留钱。不能直接声称大采购在现实中总是更好。

### 事件二：知识明码标价

英文标题：Knowledge: Now with a Price Tag。出现时间：第3天，9月13日。

情境：课程阅读清单到了，教材有不同的获取方式。学生合作社提供短期借书方案，图书馆也有免费但仅限校内使用的版本。

| 选择 | 立即效果 | 后续效果 |
| --- | --- | --- |
| 买一本自己的教材 | 支出 $90 | 文字说明可以随时阅读；没有后续退款或转售收入 |
| 合作社借书 | 支出 $40 | 第6天，9月16日，自动退回 $30，最终净支出 $10 |
| 使用校内图书馆 | 支出 $0 | 不获得可带回家的书；没有额外金钱变化 |

“借书”不是金融借款，不会产生债务或利息。退款安排是本事件设定，不是现实学校政策。当前不模拟借还书操作、学习成绩、通勤时间或迟还罚款。

反馈重点：$30 退款要到交租日之后才能使用，不能把“最终只花 $10”等同于“现在只需要 $10”。免费访问与自有教材的便利差别目前只在叙事中呈现，也正是后续需要反思的局限之一。

希望涉及的策略：比较不同方案的费用，并区分当前支付金额与未来退款。

### 事件三：蛋糕遇上房东

英文标题：Cake Meets the Landlord。出现时间：第5天，9月15日。

情境：朋友 Alex 的生日和交租日撞在一起。一个需要蜡烛，另一个需要 $500。玩家要在今天安排社交支出和必要付款。

| 选择 | 立即效果 | 后续效果 |
| --- | --- | --- |
| 参加聚餐 | 支出 $45，增加1天食物 | 可代替当天或之后一次食物费 |
| 带一道菜参加家庭聚会 | 支出 $25，增加2天食物 | 包括聚会食物及剩菜，可代替两次食物费 |
| 发一条生日祝福 | 支出 $0，不增加食物 | 保留现金；没有储备时仍需付每日食物费 |

事件发生在当天自动结算之前，因此聚会获得的食物可以抵扣当天食物费。它不能抵扣其他必要费用或房租。

没有友情值、满意度奖励或拒绝参加的惩罚。当前不能根据金额证明哪一种选择对玩家整体生活最好。生日安排没有隐藏抽奖或随机报酬。

希望涉及的策略：把计划中的社交支出与必要账单一起考虑。

### 事件四：一个下午，两份邀请

英文标题：Two Invitations, One Afternoon。出现时间：第7天，9月17日。

情境：咖啡店临时需要人手，校园食物领取也在同一时段。玩家只能选择一种安排，或保留自己的下午。

| 选择 | 立即效果 | 后续效果 |
| --- | --- | --- |
| 接额外班次 | 当天不加钱 | 第9天，9月19日，到账 $120 |
| 领取食物 | 不花钱，增加2天食物 | 可从当天开始代替食物支出 |
| 保留下午的自由时间 | 无资金和食物变化 | 不安排额外收入 |

9月18日的 $700 常规工资独立于这次选择。拒绝额外班次不会取消正常工资。兼职文案会调侃与咖啡机“谈判”失败，但这不影响约定的报酬。

这次事件已有一个简单的时间取舍：未来的钱金额较大，但今天的食物能减少今天的现金需求。保留自由时间的价值尚未通过其他数值系统体现。

希望涉及的策略：区分目前可用资源和未来收入，根据眼前付款需要作出安排。免费食物的数量、领取时段和可获得性均为虚构场景条件。

### 事件五：大米联盟

英文标题：The Great Rice Alliance。出现时间：第9天，9月19日。

情境：室友提出共同采购。群聊终于产生了未读消息以外的东西。玩家需要结合已经储存的食物判断是否继续买。

| 选择 | 立即效果 | 后续效果 |
| --- | --- | --- |
| 和室友拼单 | 支出 $35，增加2天食物 | 每天对应采购成本 $17.50，可代替两次食物费 |
| 单独买一天 | 支出 $20，增加1天食物 | 只支付较少的当期采购款 |
| 跳过这次采购 | 无支出，不增加食物 | 先消耗原有储备，没有储备时恢复普通食物费 |

本局在第10天结束，因此已有的储备很重要。多买的食物不会在结算时自动换成现金。低单位价格不代表一定需要购买。

希望涉及的策略：比较单位成本、查看已有资源，并避免只因“便宜”就购买更多。

## 七、10天时间表

| 天数 | 日期 | 当天主要内容 |
| --- | --- | --- |
| 1 | 9月11日 | 随机资金开局；食材采购选择；日末结算 |
| 2 | 9月12日 | 无新选择事件；日末结算 |
| 3 | 9月13日 | 教材获取选择；日末结算 |
| 4 | 9月14日 | 无新选择事件；日末结算 |
| 5 | 9月15日 | 生日选择；先结算生活费，再支付 $500 房租 |
| 6 | 9月16日 | 如果选择合作社借书，日初退 $30；日末结算 |
| 7 | 9月17日 | 额外兼职／食物领取／自由时间选择；日末结算 |
| 8 | 9月18日 | 日初常规工资到账 $700；日末结算 |

时间表以玩家未提前失败为前提。当前不会因为玩家穷而自动增加赚钱事件，也不会因为玩家富而自动增加消费事件。

## 八、两个可以帮助组员理解的数值例子

### 例子A：一条能够完成游戏的路线

开局 $740。依次选择：$80 批量备餐、$40 合作社借书、$25 带菜参加生日、额外兼职、$35 拼单采购。

| 日期 | 当天现金变化 | 日末余额 |
| --- | --- | --- |
| 第1天 | 买菜 -$80，其他生活费 -$10 | $650 |
| 第2天 | 其他生活费 -$10 | $640 |
| 第3天 | 借书 -$40，其他生活费 -$10 | $590 |
| 第4天 | 其他生活费 -$10 | $580 |
| 第5天 | 带菜 -$25，其他生活费 -$10，房租 -$500 | $45 |
| 第6天 | 退款 +$30，其他生活费 -$10 | $65 |
| 第7天 | 接班但尚未领钱，其他生活费 -$10 | $55 |
| 第8天 | 常规工资 +$700，普通生活费 -$30 | $725 |
| 第9天 | 额外兼职 +$120，拼单 -$35，其他生活费 -$10 | $800 |
| 第10天 | 其他生活费 -$10 | $790 |

这只是核对规则的示例，不应在说明文档中包装为唯一正确路线或现实财务建议。

### 例子B：交租前连续支出导致失败

开局同样为 $740。第1天不买菜，第3天买 $90 教材，第5天参加 $45 聚餐。前四天普通生活费共 $120，买教材后，到第5天开始时剩 $530。

聚餐花 $45，剩 $485；聚餐提供1天食物，因此当天只再扣 $10 其他生活费，剩 $475。房租需要 $500，差 $25，本轮结束。

这个例子说明单次选择“当时付得起”，不等于整段支出安排可持续。它不说明参加聚餐本身就是错误，换一种前期安排或初始资金，结果可能不同。

## 九、已经做过的测试与证据边界

实际做过的内部检查包括：

- Unity 脚本编译和真实鼠标点击。
- 日志、记账本打开与关闭，以及主要文字的布局检查。
- 选项立即扣款、食物增加和每晚消耗。
- 余额不足时禁用选项，并由游戏逻辑再次拒绝该操作。
- 未回应事件时不能推进日期。
- 同一选择不能重复领取效果；过期或错误的事件请求不能生效。
- 常规工资、教材退款和额外兼职按日期到账，不提前加入可用余额。
- 房租失败、生活费失败、完整通关和重新开局。
- 重新开局清空交易、选择和待到账款项。
- 账目中所有收入和支出的合计与余额一致。

另有一次由项目发起者转述的老师课堂试玩反馈。当前没有完成正式的大学生用户研究、前后测或长期追踪，因此不能写“已证明提升金融能力”“大部分学生觉得有趣”等结论。

### 可供核对的详细数值结果，不必放进最终 PDF

| 初始资金 | 完成的计划组合 | 房租不足 | 生活费不足 |
| --- | --- | --- | --- |
| $740 | 150 / 243 | 54 | 39 |
| $760 | 165 / 243 | 27 | 51 |
| $780 | 192 / 243 | 0 | 51 |
| 合计 | 507 / 729 | 81 | 141 |

每种开局有五次三选一，因而列出243种完整计划。若某个计划在中途失败，其后尚未发生的选择不会真的执行；不同完整计划可能共享同一段失败前缀。这个统计不是729名玩家、729次真人试玩，也不是实际玩家约70%的通关率。

按目前讨论，最终 PDF 建议只简短说明测试过不同选择组合、账目和日期，并描述降低资金后的变化。详细数字保留在本资料中作为核对依据。

## 十、金融策略依据与当前实现之间的关系

下面是指导原则与机制的对应，不代表五个事件本身已经得到实验验证。

| 原则 | 当前体现 | 当前局限 |
| --- | --- | --- |
| 记录收入和支出，并留意支付时间 | 记账本、未来账单、延迟到账收入 | 有信息不代表玩家一定会查看或使用 |
| 比较收入与费用，并随情况调整预算 | 可见余额、每日结算和事件费用 | 没有单独的预算分配操作，预留资金依赖玩家自行计算 |
| 规划食物、检查储备、比较单位价格 | 第1天备餐和第9天拼单事件 | 食物天数是简化模型，没有浪费、营养或储存限制 |

已有资料依据是 ASIC Moneysmart 的官方专家指导：

1. Australian Securities and Investments Commission. (2026, August 31). *How to do a budget*. Moneysmart. https://moneysmart.gov.au/budgeting/how-to-do-a-budget
2. Australian Securities and Investments Commission. (2026, July 30). *Ways to save on food and fuel*. Moneysmart. https://moneysmart.gov.au/budgeting/ways-to-save-on-food-and-fuel

以上来源及日期沿用2026年10月4日核对的项目资料。这些是官方指导，不是针对本游戏的效果研究。故事、价格、退款政策和食物数量是设计假设，不能写成文献证明的事实。更完整的英文对应说明见 [EventDesign.md](../Assets/Documentation/EventDesign.md)。

## 十一、老师反馈后的反思与下一步

### 已发现的问题

1. 低价或高收益选项可能太明显，玩家无需综合考虑信息。
2. 减少开局资金增加了失败风险，但难度不等于策略性。
3. 现有记录能显示选择和账目，但还不能清晰追踪某个早期决定如何限制后来的选择。
4. 社交、便利和时间的价值主要依赖文字，经济数字不足以表达这些取舍。
5. 固定的五个事件便于比较，但重玩内容很快重复。

### 拟改进方向，尚未实现

| 方向 | 拟采取的做法 | 希望通过试玩检查什么 |
| --- | --- | --- |
| 让选择依赖财务状况 | 探索“今天收到较少钱／之后收到较多钱”的互斥机会 | 不同账单压力下，玩家是否会改变选择并解释原因 |
| 加强前后事件联系 | 让前期安排影响后续可选方案，并提前提供关键线索 | 玩家是否会考虑不止当天的结果 |
| 改善回顾 | 更清楚呈现早先支出、后来资金缺口与选择之间的关系 | 玩家能否说出重玩时要调整什么 |
| 开展目标用户试玩 | 观察是否查看账单、询问选择理由，并比较再次游玩的计划 | 玩家是否真的使用了预算和收支时间信息 |

目前不应承诺所有方向都将在下一版实现。先选择一个关键取舍测试，比直接增加大量事件更容易判断设计是否有所改善。

## 十二、尚未实现的内容，写 PDF 时不要混淆

- 60天完整流程和25–35个事件的大型事件池。
- 随机抽取事件，或根据余额动态调节事件。
- 独立的开始菜单和菜单中的随机开局按钮。
- 心情、满意度、健康、友情、学习成绩或独立时间资源系统。
- 玩家借贷、利息或分期还款系统；教材事件是借书。
- 不透明的消费后抽奖、捡钱或隐藏随机财务后果。
- 可操作的预算分配、房租专用账户或自动预留资金。
- 存档、跨局历史、自动比较不同轮次和自动生成的学习报告。
- 正式目标用户研究和被验证的学习效果。

## 十三、如何把这些资料写成1–2页说明 PDF

建议使用四个简短标题：

1. **测试目的**：简述目标受众、想支持的金融策略，以及这次为何只做10天。
2. **原型与测试方法**：交代玩家主要操作、设计形式、功能检查与课堂试玩。
3. **发现与反思**：写初始资金过宽松、降低资金后的变化，以及老师指出策略体验不明显。清楚区分老师反馈和我们的分析。
4. **下一步**：选择一到两个具体改进方向，并说明准备如何检查是否有效。

可以放一张实际日志截图并标注选项、账单提示，再配一条简短流程：

**查看财务信息 → 对事件作出选择 → 即时变化与后续结算 → 查看记录 → 调整下一轮计划**

前四步已有实现；“玩家是否据此调整下一轮计划”仍需要观察，不能仅凭界面存在就当作已证实的学习过程。

### 与此次 rubric 的对应

| 评分项 | 可以引用的材料 |
| --- | --- |
| Functionality and Feasibility，30分 | 可玩的10天流程、按日期结算、按钮与账目验证、失败和重开 |
| Relevance to Game Concept，25分 | 学生情境、资金规划、付款时间和记录回顾与学习目标的联系 |
| Creativity and Prototyping Approach，20分 | 日记与记账本的组合、用有限事件测试后续影响、数值迭代 |
| Reflection and Explanation Document，25分 | 老师反馈、策略性不足的分析、测试局限和可检验的下一步 |

原型功能由可玩成果本身支撑，文档负责解释设计、证据和局限。最终还需要提交可访问的原型或演示，以及说明 PDF；源代码仓库链接不能自动等同于方便老师运行的成品。
